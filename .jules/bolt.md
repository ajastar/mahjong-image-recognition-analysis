## 2025-05-18 - [Anti-Pattern] Inlining Complex Logic for Micro-Optimizations
**Learning:** In `mahjong_logic.py`, `SafetyUtils.get_danger_score` evaluates threats per tile per player. Attempting to inline complex detections (`_detect_honitsu`, `_detect_kokushi_threat`) into a single river pass loop inside `get_danger_score` destroys encapsulation and readability for negligible gains (about 1s over 20,000 iterations). Furthermore, `import math` in the inner loop acts as an anti-pattern.
**Action:** Focus on hoisting true loop invariants (like tile properties `is_honor`, `tile_suit`, etc., and dora checks `is_dora`, `is_dora_neighbor` that are independent of the player's river) outside the `r_player` iteration block. This preserves code abstraction while still gaining measurable ~10-15% performance improvements.
