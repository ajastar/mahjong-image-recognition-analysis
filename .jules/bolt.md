## 2024-05-17 - Hot Path Object Allocation and Generator Overheads
**Learning:** In CPython, `sum(1 for x in obj if condition)` is significantly slower (~60% slower) than `len([x for x in obj if condition])` because generator comprehensions require frame allocation and continuous `next()` calls, while list comprehensions use highly optimized C code under the hood. Furthermore, dynamically building target lists (like `[0,8,9,17,18,26] + list(range(27,34))`) and testing membership using `in` within hot loops causes severe allocation overhead compared to defining a module-level `frozenset`. Finally, unrolling flat loops for list item sums is an order of magnitude faster than generator-based sum operations.
**Action:** When optimizing tight inner loops (e.g., Mahjong logic simulation paths): 1. Use `frozenset` instead of lists for membership testing (`in`). 2. Substitute `sum(generator)` with `len(list_comprehension)` or direct unrolled logic if the item count is small and fixed. 3. Avoid concatenating dynamically generated lists inside functions if the list content is static.
