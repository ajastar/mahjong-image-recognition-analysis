## 2024-05-09 - CPython Overhead of Generator Comprehensions in sum()
**Learning:** In hot-path code for CPython, utilizing generator comprehensions inside `sum()` (e.g., `sum(1 for x in obj)`) introduces considerable function call and object allocation overhead (from creating frame objects and calling `next()`). Benchmarking revealed that a C-optimized list comprehension wrapped in `len()` (e.g. `len([x for x in obj])`) is roughly 1.5x to 2x faster. Furthermore, using a loop/generator for summing exact statically known flat indices (like `sum(hand_34[t] for t in [0,8,9...])`) is significantly slower than unrolling into direct integer addition (`hand_34[0] + hand_34[8] + ...`) which avoids loop overhead entirely.
**Action:** When micro-optimizing critical loops or heuristics (like evaluating hands 100,000 times in PIMC), prefer `len([comp])` or direct unrolled addition over `sum(generator)`. Ensure these optimizations don't degrade logic correctness and are documented, given they trade slight readability for high-frequency performance gains.
