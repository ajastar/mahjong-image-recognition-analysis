## 2024-07-07 - Python Generator Comprehension Overhead in Hot Paths
**Learning:** Generator comprehensions inside `sum()` (e.g., `sum(1 for x in obj)`) introduce significant function call and iteration overhead in Python hot-paths compared to evaluating list comprehensions with `len()` (e.g., `len([x for x in obj if condition])`) or explicit `for` loops. Furthermore, evaluating boolean existence over small static collections (like checking for terminals) is extremely inefficient when using `sum()` with generator expressions over concatenated lists.
**Action:** Replace `sum(1 for x in obj)` with `len([...])` or explicit `for` loops in hot path iterations. For checking boolean state over small static domains, use a `for` loop over a module-level `tuple` or `frozenset` with an early `break`, which can yield ~90%+ speedups.
