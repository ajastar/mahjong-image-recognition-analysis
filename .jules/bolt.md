## 2024-05-19 - Cache `get_suji` Function (Duplicated across files)
**Learning:** The `get_suji` function has a very small domain (0-33 for mahjong tiles) and is called frequently in hot paths. Using `@functools.lru_cache(maxsize=34)` on such functions and changing the return type to an immutable `tuple` (instead of a list) achieves significant speedups (~35-40%) without cache pollution risks or side effects. The codebase architecture duplicates this function identically across `mahjong_logic.py`, `single_bot.py`, `factory_main.py`, `Jantama_Attach_Mode.py`, and `Background_Multi_Mahjong.py`, and requires importing `functools` everywhere it's used. As per the memory note, there's no Numba `TypingError` regressions for `get_suji` since it's not invoked from `@njit` functions.
**Action:** When applying standard Python decorators like `lru_cache` to duplicated utility functions across the codebase, ensure all affected files receive the necessary `import functools` and that the return type is changed to an immutable type (like `tuple`) to prevent accidental downstream mutation of cached objects.
