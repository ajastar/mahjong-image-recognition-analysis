## 2024-05-19 - CPython Generator Overhead in Hot Loops
**Learning:** Evaluating generator comprehensions inside `sum()` (e.g., `sum(1 for x in obj)`) introduces significant function call and iteration overhead in CPython, making it an anti-pattern for performance-critical logic like PIMC simulators. Even simple dynamic list construction (e.g., `[0,8,9] + list(range(27,34))`) becomes a bottleneck when called tens of thousands of times per turn.
**Action:** Replace `sum(1 for x in obj)` with list comprehensions evaluated by `len()` (`len([x for x in obj])`) for medium-sized operations. For tiny fixed sets (e.g., 3 Mahjong suits), use boolean addition `(a > 0) + (b > 0) == 1`. Replace dynamically built immutable lists with pre-allocated module-level constants or unroll the elements directly when aggregating properties (e.g., `val1 + val2 + ...`).
