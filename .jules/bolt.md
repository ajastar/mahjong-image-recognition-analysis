## 2024-05-18 - Replacing Dynamic Iterables in Hot Paths
**Learning:** In purely Python-based hot loops, such as evaluation and score calculations inside `mahjong_logic.py`, continuously regenerating structural references like lists of valid numbers (e.g., `[0,8,9,17,18,26] + list(range(27,34))`) causes massive garbage collection overhead and repeated list concatenations. Using generator comprehensions inside functions like `sum()` or `any()` adds significant function-call overhead that makes execution ~3-5x slower compared to using unrolled boolean math or manually unrolled explicit loops.
**Action:** When frequently iterating over standard mahjong structural indices (like terminals or honors), pre-compute these as module-level `frozenset` (for `x in set` queries) and `tuple` (for explicit `for x in tuple` loops) variables. Avoid using generator loops (`sum(1 for x in Y)`); rewrite them as standard Python `for` blocks.
