
## 2024-06-09 - CPython Generator Comprehension Overhead inside sum()
**Learning:** In CPython hot paths (like Mahjong hand evaluation or Monte Carlo simulations), using generator comprehensions inside `sum()` (e.g., `sum(1 for x in obj if condition)` or `sum(arr[i] for i in indices)`) introduces severe function call and iteration overhead (up to 4.5x slower). CPython has to execute bytecode instructions to continually yield and resume the generator on every iteration.
**Action:** Replace `sum(1 for x in obj if ...)` with C-optimized list comprehensions `len([x for x in obj if ...])` (approx 1.5-2x faster). For checking conditionals across small sets of variables, use boolean additions `(a > 0) + (b > 0) + (c > 0) == 1` (approx 3x faster). For summing small numbers of specific indices, flatly unroll the additions `arr[0] + arr[1] + ...` instead of creating loops or lists (approx 4.5x faster). Never sacrifice readability unless the code is strictly a hot-path function.
