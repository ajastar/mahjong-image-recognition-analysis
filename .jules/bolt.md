## 2024-06-07 - Generator Comprehension Overhead in CPython Hot Paths
**Learning:** Evaluating generator comprehensions inside `sum()` (e.g., `sum(1 for x in obj)`) introduces significant function call overhead in CPython. List comprehensions evaluated by `len()` (e.g., `len([x for x in obj if condition])`) or explicit loops run significantly faster, especially for small collections like Mahjong hands (34 elements) or mentsu lists (4-5 elements). Specifically, `sum(1 for m in mentsu if m[0] == 'koutsu')` is almost 2x slower than `len([m for m in mentsu if m[0] == 'koutsu'])`. For lists with fixed sizes known to be extremely small, boolean additions like `(a > 0) + (b > 0)` or list comprehensions are preferred for performance in hot paths without severely compromising readability.
**Action:** Replace `sum(1 for x in obj if cond)` with `len([x for x in obj if cond])` in performance-critical hot paths when counting elements that match a condition.
