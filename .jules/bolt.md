## 2024-05-24 - Optimizing Python Hot Paths in Mahjong Logic
**Learning:** In CPython, evaluating generator comprehensions inside `sum()` (e.g., `sum(1 for x in obj)`) introduces significant function call overhead compared to alternative approaches. For very small fixed structures (like counting elements across 3 suits), explicit boolean addition (e.g., `(a > 0) + (b > 0) + (c > 0)`) is dramatically faster. For general collections, using list comprehensions evaluated by `len()` (e.g., `len([x for x in obj])`) is faster than generator sums due to C-level list building optimizations, even though it allocates a temporary list. Furthermore, functions with small input domains called frequently in hot paths (like `get_suji` on 0-33 for Mahjong tiles) benefit heavily from `functools.lru_cache` and returning immutable types like `tuple`.
**Action:** When optimizing hot paths, replace `sum(1 for ...)` with `len([...])` or unrolled additions. Cache functions with small input domains that are called frequently.
